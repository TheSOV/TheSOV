# fragments

Small, real, runnable pieces of the thing - not pseudocode, not a description.
A fake `--help` output. One example request and its response. A sample of the
file format with real-looking values. The exact text of an error.

They exist to be argued with. A person corrects a concrete artefact and nods at
a description of one, so put the fragment in front of them early and change it
in front of them.

**Phase 4 reads these.** Whatever the `--help` fragment says is what gets
built, so a fragment that contradicts the feature note is a contradiction that
reaches the code. Keep them in step with the note by hand - the freeze protects
the note, not this folder.

Delete this file once there is a real fragment beside it.
